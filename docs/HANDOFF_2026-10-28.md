## Part 3 — Every bug found and fixed today

This is the most valuable section. Each was a real bug that would have shipped silently.

### Bug 1: Argparse mis-capture
**Symptom:** `py scripts\cohort_view.py --days 30` produced a brief with only "Learner 30" (nonexistent). DB had `['1', 'test001', 'thabo']`.
**Root cause:** `args = [a for a in sys.argv[1:] if not a.startswith("--")]` → `['30']`. Filter didn't exclude values of `--days`.
**Fix:** Replace `main()` with `argparse`. `--days` typed `int`; positional `learner_ids` uses `nargs="*"`.

### Bug 2: Silent exit
**Symptom:** `py scripts\cohort_view.py --days 30` produced no output at all.
**Root cause:** Entry point `if __name__ == "__main__": main()` was absent after a code paste that replaced the whole file.
**Fix:** Ensure entry point present at end of every code paste.

### Bug 3: Unbounded stable-learners list
**Symptom:** At n=1000, brief was 15,343 chars (target <10,000).
**Root cause:** `A(f"{len(names)} learners are progressing... {', '.join(names)}.")` — no truncation. 660 names in one sentence.
**Fix:** If `len(names) > 10`, show count only; full list in JSON.

### Bug 4: Unbounded needs-human table
**Symptom:** At n=1000, 30 needs-human rows = ~3,300 chars.
**Root cause:** Loop had no cap.
**Fix:** Top-20 with "Showing top 20 of 30" label; remainder line.

### Bug 5 (carried from 10-21): `_variant_practice_done` not persisted
Already fixed 10-21. Not re-broken.

### Bug 6 (carried from 10-21): "1 active learners" pluralization
Fixed earlier in this session via `_active_word` variable.

### Bug 7 (carried from 10-21): `data_version` drift
Fixed earlier via `ts` computed once in `generate_class_view`, passed to `build_class_plan`.

### Bug 8 (mine, in A's original spec): `_chunked_fetch` param ordering
Suspected but not proven. The test that would have failed — different numbers at 7d vs 30d — passed. Order `(*sub, *params)` is correct in final code.

### Bug 9 (side-effect): DB state drift
When `--days 30` misfired (Bug 1), brief showed "Learner 30" instead of Thabo. **False alarm** — nothing in the DB changed. The bug was in the arg parsing, not the data.

Feed actual student mistakes, not random garbage. Every failure points to a real teaching gap.

### Verify-the-wrong-answer-is-wrong (from 10-21)
Before feeding a "wrong answer" to the engine, confirm it's actually wrong. A "swap" of `x=2 or x=-1` gives `x=-1 or x=2` — mathematically identical. 56 phantom failures from this on 10-21.

### The Three-Stage Pattern (from 10-10)
1. Surgical patch — one anchor, one edit, `py_compile` after
2. Sanity check — call predicates directly
3. Realistic Tester — 20-30 scenarios

## Part 8 — Phase B scope (spec'd, not coded)

**Phase B is not "Functions." Phase B is the infrastructure for analysis at n=infinity.**

Functions is the roadmap's next topic (Q4–Q6). But per our conversation this session, the analyst layer must exist before Functions — or Functions will be built on an architecture that can't see its own data.

### The six pieces

| # | Piece | What it does | Effort |
|---|---|---|---|
| B1 | **Node tree** | `cohort_node` table with `parent_id`, precomputed rollups per level (class/school/district/province/national). O(1) queries at any N. | 1–2 sessions |
| B2 | **Correlation toolset** | Deterministic queries: slice, compare, correlate, find-anomaly. Tanaka's "what's trending" — the tools he calls. | 1–2 sessions |
| B3 | **Hypothesis ledger** | `hypothesis` table: question, data_version, finding, proposed action, predicted outcome, resolved_at, was it right? | ~1 session |
| B4 | **Flywheel write path** | `answer_source`, `lane_key`, `routing_log` (input → rung → confidence → outcome). Promotion/demotion gates. | 1 session |
| B5 | **Q&A capture** | Extend `learner_events` (NOT a second event table). Add `next_attempt_id` as a **column** (not JSON). Classifier with `unknown_speech` fallback. | 1 session |
| B6 | **Cohort membership** | Extend `learner` or add `cohort_membership` table. Needed for node tree parent-child. | ~0.5 session |

**Total: 6–8 sessions. Must be spec'd before coded.**

### What "infinity" actually means

- **The archive is append-only.** Every attempt, event, conversation — never deleted, never summarised away.
- **The node tree lets Tanaka drill to any granularity.** National → province → school → class → learner → this learner's Tuesday. He picks the depth his question needs.
- **He queries, he doesn't load.** "What did learners ask about sign-flips this month, and did my answers precede improvement?" is a query against nodes plus retrieval — not a 100-million-row read. He reads infinity by walking it.
- **Every line remains reachable forever.** Nothing is lost; the tree is an index, not a replacement.

**The honest limit:** the analyst (Tanaka-as-reader) can't exist before November when the LLM arrives. What can exist now is the archive, the index, the ledger, the reserved fields — so the LLM arrives into a system that already remembers.

## Part 9 — The design conversation (only in this chat until now)

**This is the most at-risk section.** If it isn't written down here, it doesn't exist outside our chat.

### The four-layer architecture

| Layer | Twitter analogue | What MethodMarker needs |
|---|---|---|
| **Archive** | Data warehouse | Append-only, infinite. Every attempt, question, answer, interaction. Never deleted. |
| **Index** | Precomputed dashboards | The node tree. Fast path for known questions. |
| **Query toolset** | Ad-hoc SQL + notebook | Tools Tanaka calls: slice, compare, correlate, find-anomaly, retrieve-answer-texts, compute-delta. Deterministic. |
| **Hypothesis ledger** | Experiment tracking | Every analysis logged: question, snapshot, finding, confidence, proposed action, predicted outcome. Later: did it work? |

### Tanaka as reader

- **The archive is infinite. His context per query is finite. The tree is the bridge.**
- He navigates, doesn't ingest. "What's trending in trig this week?" is a query against the trig node plus retrieval — not a full scan.
- The tree serves both readers: the teacher gets the window, Tanaka gets the drill-down.

### The analyst

Given "is this trig — what are people saying?":

1. **Slice** — filter events to topic=trig, last N days, by node
2. **Detect** — volume spike vs trailing baseline (deterministic, not a guess)
3. **Retrieve** — the actual questions and the answers Tanaka gave
4. **Correlate** — next-attempt outcome after each answer; acceptance vs rejection
5. **Check history** — does this confirm or contradict a prior hypothesis? (requires ledger)
6. **Propose** — "CAST explanation underperforms; rewrite playbook Q5.2; success criterion: acceptance rate +10pp over 3 weeks"
7. **Measure** — re-run in 3 weeks, update ledger

**Every step is a tool call with a computed result.** The LLM chooses the analysis and interprets it — it never produces the number. This is the 10-20 rule applied to analytics.

### The flywheel (route away from LLM only when proven)

| Rung | Source | Fires when |
|---|---|---|
| 1 | Deterministic rule (`diagnosis.py`) | Known misconception, high confidence |
| 2 | **Learned binding** (pattern → answer, with outcome stats) | Pattern matched, track record ≥ threshold, **lane is proven** |
| 3 | Playbook / teaching objective | Known skill, no specific diagnosis |
| 4 | LLM | Rungs 1-3 low confidence, or no match |
| 5 | LLM + human review queue | Rung 4 also low confidence |

**Rung 2 is the whole idea.** The gate is not "did we see this before" — it's **"does the learned answer beat the LLM on outcomes for this lane, by enough to trust it."** That's a calibration question, versioned like the 4-of-5 mastery threshold.

**Lane key** = `skill + misconception + question-intent`, e.g. `trig.general_solution / sign_confusion / why-question`. Lanes close individually. Some close in weeks; others never will. That's fine and should be visible.

### Guardrails

- **Math stays deterministic.** Even a promoted answer must be checked against the grader. LLM phrasing can be promoted; LLM math never bypasses the grader.
- **Premature closure is the failure mode.** A lane with 8 interactions and 7/8 is not "proven." Minimum sample + versioned threshold + reopening rule.
- **The metric is teaching outcome, not API spend.** Track accuracy/improvement per lane.
- **Drift is real.** A lane proven in 2025 is a hypothesis in 2026. Re-validate on schedule.

### Guardrails on the analyst

- **State the question before running it.** Logged in the ledger. Only defence against apophenia.
- **Minimum sample + multiplicity note.** "12 learners asked about trig" is not a trend. Every finding carries its N.
- **Causal claims are hypotheses.** "Might this be why kids are failing" is right as a hypothesis — the system designs the test, doesn't assert the cause.
- **Reproducibility.** Every analysis stores its query and data snapshot version.

## Part 10 — Critical rules (accumulated across sessions)

1. Never trust `_norm` to strip all spaces. Inside predicates, `str(x).lower().replace(" ", "")`.
2. Never use `re.sub` with backslashes in replacement. Use `str.replace(old, new, 1)` with exact anchors, or `re.sub(pattern, lambda m: replacement, src)`.
3. Never trust a set-based matcher for ordered answers. Coordinate pairs need order-preserving matchers.
4. `D_CORRECT_ROOTS_MATCH` must be guarded. Skip when fraction, unit, or y-label present.
5. `try/except: pass` in persistence code hides silent data loss. Log or raise.
6. The variant loop and main loop must share the same voice map.
7. The tester must verify its own wrong answers are actually wrong.
8. Partial credit is not correctness. Never treat `_step_awarded > 0` as a claim the answer is right.
9. The retention scheduler distinguishes `pending`, `passed`, `failed`, `missing`, `dismissed`. Missed ≠ failed.
10. When running PowerShell with wildcard, use `Get-ChildItem | Start-Process`, not `start *.json`.
11. **Every section that lists names needs a truncation threshold.** (New — this session.)
12. **Argparse values must be typed.** (New — this session.)
13. **Silent exit means missing entry point.** (New — this session.)
14. **When a run produces unexpected data, check the DB before assuming a bug.** (New — this session.)
